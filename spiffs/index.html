Wi-Fi Setup

Scan nearby networks and connect the helmet to one of them.

Network scanning needs a firmware endpoint: GET /api/wifi/scan. The current firmware only exposes /api/status.

Known Network Strategy

How the firmware should choose a network: scan, compare against saved credentials, then connect to the strongest match.

1. Browser requests a Wi-Fi scan.

2. ESP8266 runs esp_wifi_scan_start().

3. Firmware compares scanned SSIDs against saved credentials.

4. The strongest matching network is selected by RSSI.

5. Firmware calls esp_wifi_set_config() then esp_wifi_connect().

Danger Thresholds

These limits decide when a sensor reading counts as a warning. They should be saved to NVS or SPIFFS so they survive a restart, not hardcoded in app_config.h.

This UI sends gas, flame, computed heat index, and distance limits to POST /api/config/thresholds.

Hardware Pins

Configure sensors, warning LEDs, and the buzzer. Save, then restart if your firmware requires restart to apply pins.

ESP8266 has only one internal analog input, A0. If gas and flame are both analog, use an external ADC or multiplexer.

System Actions

Use these to test the buzzer alarm and restart the ESP8266.

These actions call POST /api/alarm/test and POST /api/system/restart.
